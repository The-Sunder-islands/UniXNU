# A540 C1/C2 基线：GPU 供电与时钟（2026-11-09）

本文件把 C1（供电）和 C2（时钟）整理成可直接复用的基线。实验历史见
`STATUS.md` 的 H221–H236g，寄存器推导见
`A540-C1-gpu-power-2026-11-08.md`。

## 1. 已验证状态

```text
SPMI PMIC arbiter v3      core 0x0800f000 / chnls 0x08400000 / obsrvr 0x09400000 / cnfg 0x0800a000
PM8005 S1 (SID 5, 0x1400) FTS426（type 0x1c / subtype 0x0a），common2 布局
                          APID 1, owner EE0, 写用 EXT_WRITEL（opcode 0）
                          电压 752 mV，MODE 7 (HPM)，ENABLE=0x80
GPUCC GX GDSCR (0x1094)   a0282000，PWR_ON=1
Fabia PLL (gpupll0)       L=53, alpha=0x8aab → VCO 1028 MHz，even /2 = 514 MHz，LOCK=1
gfx3d_clk_src             0x1074=0x101（even 源、div 1）→ 257 MHz
gfx3d 根 0x1070           0x00000002（ROOT_ENABLE=1，ROOT_STATUS=0）
gfx3d 分支 0x1098         0x00002621（bit31=0，已开）
RBBM 0x5000000            0x00010042 / 0xb5f00000 / 0x00000000
```

完整链路：

```text
SPMI → PM8005 S1（752 mV / HPM / enable）
  → GX GDSCR PWR_ON
  → Fabia PLL 1028 MHz 锁定
  → gfx3d 根 257 MHz
  → 分支使能
  → RBBM 可读
```

## 2. SPMI 传输（msm8998 v3 数据通路）

仲裁器版本 `core+0x0 = 0x30000000`，v3 与 v2 共用 PPID 映射、通道页和 CMD 格式。

```text
PPID       = (sid << 8) | (addr >> 8)        5, 0x1400 → 0x514
通道页     = 0x1000*ee + 0x8000*apid          ee=0 → 0x8000*apid
CMD        = (opcode << 27) | ((addr & 0xff) << 4) | (byte_count - 1)
读         = obsrvr + 页 + {CMD 0x00, STATUS 0x08, RDATA0 0x18}
写         = chnls  + 页 + {WDATA0 0x10, CMD 0x00, STATUS 0x08}
STATUS     = bit0 DONE；bit1 FAILURE，bit2 DENIED，bit3 DROPPED
APID 映射  = core + 0x800 + 4*apid，PPID [19:8]
写拥有者   = cnfg + 0x700 + 4*apid，[2:0] 必须等于 EE0
```

opcode：

| opcode | 用途 | 结果 |
| --- | --- | --- |
| 15 | 标准读 | 本片可读到正确身份/电压 |
| 14 | 标准写 | STATUS DONE，但 PMIC 不更新 |
| 2 | 8 位扩展写 | STATUS DONE，但 PMIC 不更新 |
| **0** | **EXT_WRITEL（16 位寄存器号）** | **写入生效** |

PM8005 的 QPNP 寄存器用 16 位寄存器号（如 `0x1446`），厂商 regmap 走
`spmi_ext_register_writel` → `PMIC_ARB_OP_EXT_WRITEL` (0)。这是 H236f 的关键。

## 3. PM8005 S1（FTS426，common2）

```text
0x1401 REV=0x00     0x1404 TYPE=0x1c    0x1405 SUBTYPE=0x0a
0x1440/0x1441       16 位小端电压，单位 mV（0x02f0 = 752 mV）
0x1445 MODE         3..7，6=AUTO，7=HPM
0x1446 ENABLE       bit7=1
0x1461 STEP_CTRL    0x81
```

- 板级 `regulator-min-microvolt = <524000>`，FTS426 的 4 mV 网格上 524 mV 合法；
- 当前寄存器已存 752 mV；C1/C2 基线直接保留该值，不重写电压；
- `PM8005 S1 + S4 = 2 phase VDD_GFX`，本轮只驱动 S1；若 GX 不 PWR_ON，下一候选是
  S4（0x1d00，同一 common2 布局）。

## 4. GPUCC 寄存器与 C2 序列

```text
0x0000 PLL MODE     bit31 LOCK, bit30 ACTIVE, bit22 UPDATE, bit2 RESET_N, bit0 OUTCTRL
0x0004 PLL L_VAL
0x0008 PLL CAL_L_VAL
0x000c PLL USER_CTL_LO   [11:8] even post-div（1 = /2），[3:0] main output (7)
0x0010 PLL USER_CTL_HI
0x0014 PLL CONFIG_CTL
0x002c PLL OPMODE   0 = standby, 1 = run
0x0038 PLL FRAC     alpha（16 位）
0x0130 GX clamp
0x1004 CX GDSCR / 0x1008 CX GDS_HW_CTRL
0x1070 gfx3d CMD_RCGR   bit0 UPDATE, bit1 ROOT_ENABLE, bit31 ROOT_STATUS (RO)
0x1074 gfx3d CFG_RCGR   [4:0] div, [10:8] src（1 = even PLL output）
0x1090 GX BCR
0x1094 GX GDSCR
0x1098 gfx3d branch
```

C2 顺序：

1. `L=53, CAL_L=53, FRAC=0x8aab` → VCO 1028 MHz；
2. `MODE` 清 OUTCTRL，`OPMODE=0`，`MODE |= RESET_N`，`OPMODE=1`，等 LOCK；
3. `USER_CTL_LO |= 7`，`MODE |= OUTCTRL`；
4. `CFG_RCGR=0x101`，`CMD_RCGR |= bit0`，等 bit0 清零；
5. `CMD_RCGR |= bit1`，等 bit31 清零；
6. 分支 `0x1098 = (old | bit13 | 1) & ~bit31`。

注意：

- `CMD_RCGR` 的 bit31 是只读状态；H227 清 bit31 而不置 bit1，所以根时钟一直没开；
- branch 写后立即读可能仍是 `0x80002621`，下一次 1 Hz survey 会读到 `0x00002621`，
  不要用立即读判定失败。

## 5. 启动模式与结果通道

`sheng-gpu-power`：

| 值 | 行为 |
| --- | --- |
| 1 | C1b/C1c 旧序列（保持不变） |
| 2 | PM8005 S1 只读 survey |

## 7. 已知问题/注意

1. 干净重建可能漏掉 `zzz-root-auth-bypass.patch`，导致 `bsd_init.c:1103` 提前 panic；
   构建后检查 `strings kernel | grep NATIVE_ROOT_AUTH_BYPASS`，缺了要补 patch 再重建。
2. 构建机 `build-xnu-4k-baseline.sh` 的补丁循环对已打补丁的树不是幂等的；本轮
   先重置 `xnu-work`，bootstrap 一次性应用 114 个 patch，再用
   `XNU_SKIP_PATCH_LOOP=1` 跑最终构建。
3. 驱动对象不随内核自动重编；改 `NativeLegacyProbeSupport.cpp` 后必须先跑
   `scripts/build-op5-legacy-display.py`，再链接内核。
4. `gfx3d` 分支启动有延迟；看下一次 survey 的 `0x1098`。
5. 只做 `fastboot boot`；不写 boot/userdata/GPT/固件分区。

## 8. 下一步（C3）

1. 读 RBBM/A5xx 身份寄存器确认 A540 chip ID；
2. 只读 survey GMU/CP 寄存器基址与固件状态；
3. 加载 `a540_gpmu.fw2` / `a540_zap`（addon 已带 GPU 固件），按 A5xx GMU 冷启动
   顺序投票 CX/GX、解复位、启动 GMU；
4. GMU 起来后再初始化 CP/RB/微码，最后进入 kgsl 的 GPU 命令队列。

C3 的第一张镜像应只做 1–2（只读），确认基址和固件头，再做 3 的写入。

## 9. C3 起点：只读 A5xx survey（H236h）

`sheng-gpu-power=5` = C2 + 只读 CP/GPMU/RBBM survey。偏移 = `a5xx_reg.h` 的
dword 索引 ×4：

| 偏移 | 名称 | 预期/用途 |
| --- | --- | --- |
| 0x2000 | cp_rb_base | ringbuffer 基址（未初始化应为 0） |
| 0x2008 | cp_rb_cntl | RB 控制 |
| 0x2018 | cp_rb_rptr | 读指针 |
| 0x201c | cp_rb_wptr | 写指针 |
| 0x20c8 | cp_me_cntl | ME 控制/复位状态 |
| 0x20d4 | cp_pfp_instr_base | PFP 微码基址 |
| 0x1384 | rbbm_int0_status | 中断状态 |
| 0x13d4 | rbbm_status | RBBM 忙/挂起状态 |
| 0x14c0 | rbbm_status3 | RBBM 扩展状态 |
| 0x2a360 | gpmu_cm3_sysreset | GPMU CM3 复位 |
| 0x2a380 | gpmu_general0 | 初始化后应为 0xBABEFACE |
| 0x2a384 | gpmu_general1 | 错误码 |
| 0x22000 | gpmu_inst_ram0 | GPMU 指令 RAM 首字 |

结果 `gc=114..126`。这一轮不写任何 CP/GPMU 寄存器；某块未授时钟时读可能挂住，
最后一个 gc 即停点。

C3 写入顺序（厂商 `adreno_a5xx.c`）：

1. RBBM/CP 软复位、开 RBBM/CP 时钟；
2. 加载 `a530_pm4.fw` / `a530_pfp.fw` 到 CP 微码 RAM；
3. 初始化 CP ringbuffer（`CP_RB_BASE/CNTL/RPTR/WPTR`）；
4. 用 CP type4 包把 `a540_gpmu.fw2` 写进 `A5XX_GPMU_INST_RAM_BASE`；
5. `GPMU_CM3_SYSRESET=0`，轮询 `GPMU_GENERAL_0 == 0xBABEFACE`；
6. 再做 GMU 电源投票、SMMU、CP/RB 队列和 kgsl 提交路径。

H236h 产物：kernel `f9f4e043…`、payload `fd190a42…`、boot `bf2faa24…`。
